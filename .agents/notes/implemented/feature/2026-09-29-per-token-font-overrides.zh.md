# Agent Note: 以设置表呈现的逐 token 字体覆盖

Status: implemented

[English](2026-09-29-per-token-font-overrides.md) | 中文

## Problem

排版此前只能通过两条整数轴调整（会话正文与工作区文档，10–22 px）。其余所有字体 token——三个字体族、Markdown 阶梯、代码族、界面文字尺度——都固化在 `gradient-shadow-text.css` 里。若出厂字栈不可读（缺少中文回退、首选字体本机不存在），或用户需要在会话里看到更大的代码，除了改插件样式表别无他法；改坏之后也没有退路。两条轴同时缺乏可见性：产品里没有任何地方说明哪个 token 绘制哪个元素。

## Decision

`@deepseek-ai/dsh-client-ui-theme` 拥有一个封闭的排版目录（[font-catalog.ts](../../../../packages/client/ui-theme/src/font-catalog.ts)），并由「通用」设置的一行把它以表格形式打开（`token | 字体族 | 字号 | 用途`）。每个目录条目给出一个简写 token、以本地化文案说明它绘制的元素、一段用该 token 实时值渲染的自演示示例、出厂字号与行高比例，以及它内嵌的内置字栈；那些没有功能组件消费的 token（`--dsw-font-l-20`、`-m-18`、`-base-16`）刻意不列入，因此表里不会出现改了也没有效果的控制项。字体族只能从四个精选字栈中选择；自由输入被拒绝，因为非法字栈正是这张表要修复的那类故障。

一次编辑会把 `{ token, size?, family? }` 固定到 `ui-theme` 命名空间新增的可选 `fonts` 数组（`FONT_OVERRIDES_FIELD`）。快照同时发布原始固定项与其到 CSS 的投影（`fontTokens`，由 `fontOverrideLayer` 构建），而文档呈现器——本就是两条轴的投影路径——把这些 token 写成 body 上的内联自定义属性，从而压过样式表阶梯；Host 启动脚本在首帧前写入同一份投影。字号按各条目自身边界钳制，线上 schema 拒绝未知 token、未知字栈与超界字号。两条字号轴仍通过各自既有的持久字段编辑，而非固定列表，因此字号轴保持自身语义。

恢复是显式的：行内「恢复默认」移除该固定项（或把字号轴复原为 14 px），底部的「全部恢复默认」经确认后一并清空该字段与两条轴。入口行会计数已固定的 token 与已改动的字号轴，因此出厂组合不会在用户不知情的情况下被替换。

## Alternatives considered

**暴露全部 `--dsw-font-*` token，包括无人引用的尺度。** 列出没有组件消费的 token 只会教用户去改无效项，并让真正重要的行淹没在四十行里；封闭目录本身就是这个特性，而不是限制。

**允许自由输入字体栈。** 用户对目标的原话是「以免我不要改错」；接受任意 CSS 等于欢迎一个让界面无法阅读的拼写错误，而恢复路径将成为唯一防线。

**做成独立插件。** token、它们的默认值、投影路径与持久化都属于 theme 拥有者；另起插件需要新开一条 seam 才能写入，而仓库规则是每个 feature 拥有自己的设置面。

**通过主题覆盖层（`ctx.theme.overrideTokens`）改样式表。** 那一层是别名 token 的调色板 seam，按配色方案成对取值；字体与配色无关，把它们放进去会让两个独立演进的关注点纠缠在一起。

**让工作区预览跟随被固定的 Markdown 或代码字号。** 预览根承载排版阶梯并把正文轴重绑到工作区轴，因此 body 级固定项在构造上无法到达它。目录在这些行的说明里如实写出，而不是另造一条固定路径。

## Consequences

被固定的 token 是绝对值：该条目在被恢复前不再跟随字号轴，表里会标明哪些行已被固定。工作区预览继续跟随工作区轴（含其代码族），受影响的各行在自己的说明里写明了这一点。目录从此是一份需要维护的契约——某个 token 获得或失去最后一个消费者时，必须相应加入或移出目录，而 `FONT_ITEMS` 同时供给设置 schema 的 token 联合与这张表。验证分布在目录、控制器、呈现器、对话框、入口行、Host schema 与组装后的 apply 各 spec 中：投影、钳制、拒绝未知 token、两条恢复路径，以及启动脚本携带固定项。
